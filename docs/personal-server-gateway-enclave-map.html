Workflows

Register PS Enclave
  1. Vana Web App asks the Gateway to prepare the user’s enclave identity.
  2. The Gateway places an identity-only request on an attested TEE orchestrator.
  3. The orchestrator derives the deterministic wallet via dstack KMS and returns only the public identity and attestation evidence. No sandbox starts.
  4. Vana Web App verifies the evidence, shows the identity, and asks for consent.
  5. The owner signs. Vana Web App submits the registration to the Gateway, which records it and settles on-chain.
  6. Vana Web App sends the owner’s master-key signature, encrypted to the attested TEE. The Gateway relays it blind.
  7. The TEE seals the signature under a user-scoped KMS key. Only ciphertext is stored.
  8. Prewarm: the orchestrator provisions the user’s sandbox, injecting the wallet and unsealed data root. The PS Enclave now exists, until its idle TTL.
Raw read · PS Enclave
  1. Builder App sends a signed read request: grant, scope, deadline. No user data.
  2. The Gateway verifies builder and grant and queues the job. A TEE orchestrator with capacity claims it.
  3. The orchestrator derives the user’s wallet, unseals the master-key signature, and starts or reuses the user’s sandbox with only that key material.
  4. The PS Enclave fetches only the granted scope’s encrypted files from Vana Storage and decrypts them inside the sandbox.
  5. The PS Enclave re-checks the grant and returns the result encrypted to the builder’s key.
  6. The Gateway returns ciphertext. Builder App decrypts.
Private inference
  1. Builder App encrypts the question to the user’s registered PS Enclave key and sends it with signed job metadata.
  2. The Gateway verifies builder and grant and queues the job. A TEE orchestrator claims it; inference never routes to PS Full.
  3. The orchestrator derives the user’s wallet, unseals the master-key signature, and starts or reuses the user’s sandbox with only that key material.
  4. The PS Enclave fetches only the source scopes’ encrypted files from Vana Storage and decrypts them inside the sandbox.
  5. The PS Enclave checks the question against owner consent, builds a bounded prompt, and encrypts it to the attested Private Inference key. The Gateway relays the bytes blind.
  6. Private Inference returns the answer encrypted to the PS Enclave’s ephemeral key.
  7. The PS Enclave decrypts the answer, keeps lineage owner-side, and returns only the answer encrypted to the builder’s key.
  8. The Gateway returns the answer ciphertext. Builder App decrypts; source data never left the sandbox.
Wake PS Enclave
  1. After login, Vana Web App asks the Gateway to prewarm the user’s PS Enclave.
  2. The Gateway checks for an active sandbox. If none, it selects a TEE with capacity and places a startup assignment.
  3. The orchestrator derives the same wallet, unseals the master-key signature, and starts the sandbox with only that user’s key material.
  4. The sandbox hydrates encrypted files from Vana Storage as jobs need them and stays warm for an activity TTL.
Scale out · add TEE 2
  1. An operator provisions a new TEE with the same pinned app_id and image, and registers it with the Gateway.
  2. The new node answers the Gateway’s attestation challenge.
  3. The node verifies its PS image, passes a KMS canary, and heartbeats ready.
  4. The operator admits it. The Gateway can now place any user’s sandbox here.
  5. Scale-down: the operator drains the node, then destroys it.
