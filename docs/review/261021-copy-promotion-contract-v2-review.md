Chain binding and adversarial checks

copyKey is a local retention key, not a value recoverable from the chain. Its ordered ABI-encoded commitment vector matches dpv2.ts:34-60,97-109; envelopeDigest remains the canonical JSON SHA-256 (Lite canonical-store.ts:62-66). transport.ts:96-120,156-199,209-250 binds owner/writer/batch/index/count/digest/predecessor and verifies complete assembly. A genuinely shorter valid copy changes the index-0 commitment through count/header/content; dropping tail elements must fail validation, not produce a shorter valid vector. Different fragmentation can share an envelopeDigest, so V2:18's explanation that every different copy has a different digest is too strong, though commitment selection remains sound.

For well-formed inputs, zero copies plus unknown/absent waits; zero copies plus committed evidence refetches; partial finality waits unless every candidate is already disproved; ordinary absence does not disprove; incompatible committed history terminates; corrupt matching claims cannot promote. Budget is batch-scoped and never resets on a new key. These are substantial improvements. Branch coverage alone does not make the outputs/transitions total.

Add readView/previewRows, readConnectionPage and readBlob to §4; confirmed-blobs must not remain an unconditional bypass after terminal conflict. Node implementation feasibility remains unverified.

2. P1 — Quarantine output is not fully specified. V2:135 only constrains membership; :159-161 defines exact membership only for wait. Refetch/owner with one disproved copy can therefore leave it pending and grant-visible under include-pending. Promote/reconcile likewise lack an exact all-other-valid rule. Terminal must include the formerly promoted copy, contrary to :135's blanket exclusion. Define each branch's exact set AND reason. At :171 explicitly exempt a duplicate of the promoted key; otherwise replay says both “new copy is quarantined” and “confirmed copy untouched.”

3. P1 — Corrupt-first arrival can permanently occupy a valid copy's key. V2:25,49-59,65,134 keys by claimed commitment vector, fixes validity forever and deduplicates by that key. Store corrupt attempts under a separate diagnostic/actual-byte identity; they must not reserve the validated-copy key. Specify duplicate-key consistency checks rather than choosing an arbitrary representative.
